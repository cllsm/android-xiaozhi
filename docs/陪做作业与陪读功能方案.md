# 陪做作业与陪读功能方案

## 1. 结论

**可以实现，且大部分基础设施已经就绪。** 本仓库现有的相机拍摄、视觉分析服务、MCP 工具框架、语音前台服务和服务端 ASR 转写回流，已经构成“看见题目/书页 + 听懂孩子说话 + 开口讲解反馈”的完整闭环。新增功能可以完全按照现有模块风格落地，不需要推翻任何架构。

两点前提需要先说清楚：

1. **视觉识别质量依赖服务端视觉服务**（`VisionService` 使用的 HTTP 端点由服务端通过 MCP capabilities 下发）。打印体文字识别已经可用；手写体作答、数学公式、拼音标注的准确率需要在 Phase 0 用真实样本验证，识别不稳的场景用“拍不清就问孩子”兜底。
2. **对话人格由服务端 LLM 驱动**，客户端主要通过 MCP 工具描述和工具返回内容注入教学规则（现有 `ScreenshotTool` 等已经这样使用）。这是纯客户端可落地的路径，但属于概率性约束；若服务端可配置 system prompt（自建服务器的用户），建议同步配置“陪学导师人格”作为强化手段。

## 2. 场景与目标

### 2.1 用户故事

**陪做作业**

- 孩子写作业时说“小智小智，陪我写作业”，进入作业模式。
- 孩子指着本子问“第 3 题怎么做”，小智拍下当前页，先给提示而不是答案，孩子还是不会再逐级讲解。
- 孩子说“帮我检查一下”，小智拍页识别作答，逐题给出批改结果，错的题引导订正。
- 家长事后在手机上查看本次作业报告：时长、检查了哪些题、哪些题订正过、哪些知识点薄弱。

**陪读**

- 孩子说“小智小智，陪我读这本书”，拍下书页进入阅读模式。
- 领读模式：小智读一句，孩子跟一句；孩子读错、漏字时温和指出。
- 自由阅读时孩子问“这个词什么意思”，小智结合当前页面内容回答。
- 读完生成阅读报告：读了多少字、准确率、卡壳的字词、鼓励语。

### 2.2 目标

1. 做成独立的“陪学模式”，与现有闲聊、音乐场景隔离，有明确开始与结束。
2. 教学策略默认“引导优先”，不直接报答案；直接答案由家长解锁。
3. 陪读评测在客户端本地完成（OCR 一次 + ASR 回流逐句对比），不额外增加服务端接口。
4. 会话数据本地保存，家长可查看、可导出、可删除。
5. MVP 阶段相机按需拍摄（孩子说“看这题”或点按钮才拍），不做连续监控，降低隐私与功耗压力。

### 2.3 非目标（本方案不做）

- 不做自动写作业、代写作文。
- 不做长时间无人值守的儿童看护监控。
- 不内置题库与离线批改引擎（走视觉识别 + LLM 路线）。
- 不做拍照搜题第三方服务接入（可留作后续扩展位）。

## 4. 总体设计

### 4.1 架构

新增一个 `study/` 包，作为陪学域的唯一入口，其他模块只通过它交互：

```text
ui/XiaozhiApp.kt            新增 Screen.Study 与两个模式页面
        │
study/StudySessionState     会话状态机（模式、阶段、计时、当前页缓存）
study/StudySessionManager   开始/暂停/结束、计时器、休息提醒
study/HomeworkPromptBuilder 作业页识别/批改/讲解提示词
study/ReadingPromptBuilder  书页文本提取/理解问题提示词
study/ReadingEvaluator      转写与原文的逐句对齐评测（本地）
study/StudyTools            MCP 工具：拍页、查缓存、批改、计时、报告
data/StudySessionRepository 会话报告与陪学设置持久化
```

数据流：

```text
拍照/说“看这题”
  → StudyTools（MCP 或 UI 直调）→ HomeworkPromptBuilder → VisionService
  → 结构化题目列表缓存进 StudySessionState
  → 服务端 LLM 基于工具结果讲解（受三级提示策略约束）
  → 孩子朗读（仅陪读）→ 服务端 ASR final 回流
  → ReadingEvaluator 本地对比 → UI 高亮 + 语音反馈
  → 结束会话 → StudySessionRepository 落盘报告
```

### 4.2 陪学模式状态机

```text
StudyMode: None | Homework | Reading
StudyPhase: Prepare | Active | Break | Summary
```

- `Prepare`：检查相机权限、语音服务连接、视觉服务就绪；陪读还需首次拍页建立“当前页”。
- `Active`：正常互动；作业模式维护题目缓存，阅读模式维护句子指针。
- `Break`：专注计时到期，播报休息提醒，倒计时后回到 Active。
- `Summary`：生成本次报告，展示后回到 None。

状态放进 `StudySessionState`（单例 StateFlow），UI 与 `StudyTools` 共享同一数据源。

### 4.3 关键机制：客户端如何约束服务端 LLM 的教学行为

1. **工具描述注入规则**：每个陪学 MCP 工具的 `description` 写明“引导优先、三级提示、默认不给最终答案、多用鼓励语气”，与现有 `ScreenshotTool` 的详细中文描述风格一致。
2. **工具结果附带行为指令**：例如 `homework_get_context` 返回的 JSON 中带 `teaching_rules` 字段，写明当前题处于第几层提示、答案策略是什么，LLM 在生成回复时会参考。
3. **答案策略开关**：`AnswerPolicy.GuidanceOnly`（默认）与 `GuidanceThenAnswer`（家长解锁），策略写入工具结果；设置页用“家长验证”（简单 PIN 或系统生物识别）解锁。
4. **服务端强化（可选、非阻塞）**：文档随附一段推荐的陪学导师 system prompt，供自建服务端用户粘贴配置；不改服务端也能上线 MVP。

## 5. 功能设计

### 5.1 陪做作业

**进入方式**

- 语音：“陪我写作业 / 开始作业模式”（由 LLM 调 `study_start` 工具或客户端本地意图拦截）。
- UI：陪学中心点“陪做作业”。

**页面识别（拍一次，用多次）**

孩子说“看第 3 题”时拍当前页，`HomeworkPromptBuilder` 要求视觉服务返回结构化 JSON：

```json
{
  "page_type": "worksheet|textbook|exercise_book",
  "subject_guess": "数学",
  "items": [
    {
      "index": 3,
      "question": "……",
      "question_type": "calculation|fill_blank|choice|application|unknown",
      "student_answer": "……",
      "answer_readable": true,
      "confidence": 0.82
    }
  ],
  "unreadable_regions": ["第 5 题手写字迹较淡"]
}
```

结果缓存进 `StudySessionState`，之后“第 3 题再讲一遍”不再重新拍照（除非孩子说“重新看”）。

**三级讲解（核心教学策略）**

| 层级 | 内容示例 | 触发 |
| --- | --- | --- |
| L1 读题找关键 | “这道题让我们算什么？它考的是两位数进位加法哦。” | 首次提问 |
| L2 给思路第一步 | “先看个位，7 加 5 会超过 10 吗？” | 孩子说“还是不会” |
| L3 完整步骤讲解 | 分步讲透，最后一步留给孩子自己算并说出结果 | 孩子再要一次提示 |
| 直接答案 | 默认锁定 | 家长解锁后，且 L2 之后才允许 |

层级记录在题目缓存里，同一题连续追问自动升层；孩子换题则重置。

**检查作业**

- 孩子说“帮我检查”或点按钮 → `homework_capture_page`（`intent=check`）重新拍照 → 识别最新作答 → 逐题给 `correct | wrong | unreadable | blank`。
- 批改结果进 UI 列表，语音只播报总结（“一共 6 题，4 题对了，第 2 题和第 5 题我们再看看”）。
- 错题进入“订正队列”，订正后再拍一次验证，报告记录订正轨迹。

**专注计时与提醒**

- 默认 25 分钟专注 + 5 分钟休息（可在设置调整，儿童默认建议 20/5）。
- 到点由客户端本地提醒（TTS 播报 + 通知），不依赖服务端。
- P1 再加坐姿/用眼提醒：每 5 分钟拍一帧只做姿态判断，帧用完即弃、不落盘、不用于识别作业内容。

**会话报告**

```json
{
  "id": 123,
  "mode": "homework",
  "started_at": 1730000000,
  "duration_minutes": 32,
  "subject": "数学",
  "items": [
    {"index": 3, "state": "correct_after_hint", "hint_levels_used": 2},
    {"index": 5, "state": "corrected", "first_check": "wrong"}
  ],
  "focus_streaks": [20, 12],
  "weak_points": ["进位加法"]
}
```

报告只在本地存储，家长在陪学中心按天查看，支持导出 JSON 与一键删除。

### 5.2 陪读

**页面文本提取**

拍一次书页，`ReadingPromptBuilder` 要求按行/句返回：

```json
{
  "title_guess": "……",
  "page_number_guess": 42,
  "sentences": [
    {"index": 1, "text": "春天来了，……"},
    {"index": 2, "text": "……"}
  ]
}
```

**领读模式（半双工轮替）**

小智读第 N 句（TTS）→ 轮到孩子读同一句 → ASR final 回流 → 本地评测 → 鼓励或温和指出 → 下一句。轮替设计避免 TTS 回声进麦克风，也符合跟读教学节奏。

**跟读评测（客户端本地完成）**

`ReadingEvaluator` 对比“期望句”与“转写句”：

1. 字符级编辑距离：检测漏字、多字、换字。
2. 拼音级对比（pinyin4j）：把替换字进一步分为“同音/近音错读”与“真错读”，同音多数情况可放过或轻提示。
3. 输出：准确率、错读字列表、漏读片段、是否建议重读本句。

评测结果写入 `StudySessionState`，UI 高亮当前句与错字；同时把简短结果文本通过现有 `sendText` 通道发给服务端，让 LLM 生成符合导师人格的鼓励反馈（例如“第 2 句里‘美丽’漏掉了，跟小智再读一遍好不好？”）。

**自由阅读问答**

孩子问词义、剧情时，LLM 调 `reading_get_context` 拿当前页句子缓存作答，避免重复拍照；问题需要看新页时才调 `reading_capture_page`。

**理解问答（P1）**

每页读完后小智主动问 1 个理解问题（谁、为什么、接下来会怎样），回答由 LLM 判定并记录进阅读报告，帮助家长了解理解情况而非只看流畅度。

## 6. 技术设计

### 6.1 MCP 工具清单

新增 6 个工具（沿用 `McpTool` 接口，按现有分页机制自动处理描述体积）：

| 工具名 | 作用 | 关键参数 |
| --- | --- | --- |
| `study_start` | 进入陪学模式（作业/阅读），返回当前状态与教学规则 | `mode` |
| `study_status` | 查询模式、阶段、计时、当前页缓存摘要 | 无 |
| `homework_capture_page` | 拍当前作业页并按问题意图识别/批改 | `intent: explain\|check\|refresh`, `question_number` |
| `homework_get_context` | 返回缓存题目与讲解层级，不拍照 | `question_number` |
| `reading_capture_page` | 拍书页提取句子 | `intent: initial\|next_page` |
| `reading_get_context` | 返回当前页句子缓存（含当前跟读句） | 无 |

计时、休息、结束会话由客户端 UI 与本地状态机管理，不暴露为 LLM 工具，避免模型误操作计时器。

### 6.2 数据模型

新增 `study/StudyModels.kt`：

```kotlin
enum class StudyMode { None, Homework, Reading }
enum class StudyPhase { Prepare, Active, Break, Summary }
enum class AnswerPolicy { GuidanceOnly, GuidanceThenAnswer }

data class StudySettings(
    val childGrade: String = "三年级",
    val defaultSubject: String = "数学",
    val answerPolicy: AnswerPolicy = AnswerPolicy.GuidanceOnly,
    val focusMinutes: Int = 20,
    val breakMinutes: Int = 5,
    val postureReminderEnabled: Boolean = false
)

data class HomeworkItem(
    val index: Int,
    val question: String,
    val questionType: String,
    val studentAnswer: String?,
    val answerReadable: Boolean,
    val confidence: Float,
    var hintLevel: Int = 0,
    var checkState: String = "unchecked" // unchecked/correct/wrong/blank/unreadable/corrected
)

data class ReadingSentence(
    val index: Int,
    val text: String,
    var status: String = "pending" // pending/reading/passed/needs_retry
)

data class StudySessionRecord(
    val id: Long,
    val mode: StudyMode,
    val startedAt: Long,
    val endedAt: Long,
    val summaryJson: String
)
```

### 6.3 提示词模板要点

`HomeworkPromptBuilder` 按意图分三套模板（对齐 `ScreenVisionPromptBuilder` 的结构）：

- **explain**：只提取题干与已知条件，标注手写作答是否可读，不要求给答案。
- **check**：逐题提取作答并判断对错，输出结构化批改数组；不确定的标 `unreadable`，禁止臆造。
- **refresh**：只更新作答区域，题干沿用缓存，降低视觉服务负担。

`ReadingPromptBuilder` 两套：`extract`（按句拆分页面文本）、`question`（基于页面生成一个理解问题）。

所有模板都要求：只处理可见内容、模糊就明说、输出中文 JSON。

### 6.4 ASR 回流接入点

`VoiceForegroundService` 的 `stt` 分支已有音乐意图拦截先例。陪读模式下在同一位置追加：

```kotlin
if (StudySessionState.mode == StudyMode.Reading) {
    StudySessionManager.onChildTranscript(text)
    return  // 转写交给陪读评测，不再当普通聊天处理
}
```

`onChildTranscript` 内部完成对齐、更新状态、生成反馈文本并走 TTS 通道播报。

### 6.5 存储方案

- MVP 用 DataStore Preferences + JSON 字符串存最近 30 条会话报告（量小、结构简单，避免引 Room）。
- 陪学设置并入 `SettingsRepository` 新增字段，或独立 `StudySettingsRepository`；建议独立，避免主设置页一次塞太多。
- 图片全程只在内存中处理，不写入磁盘（现有 `CameraCaptureController` 已是如此），报告里只存结构化文本。

### 6.6 UI 设计

新增 `Screen.Study`（陪学中心），入口放在首页：

- 两个模式入口：陪做作业、陪读，进行中的会话显示计时与当前状态。
- 作业页：题目列表（状态徽标）、“拍当前页”“检查作业”“讲解第 N 题”按钮、订正队列、结束并生成报告。
- 阅读页：句子列表、当前句高亮、错字标红、准确率、上一句/下一句、结束报告。
- 历史报告列表：按日期查看、导出、删除。
- 设置页新增“陪学”分组：年级、默认学科、答案策略（家长解锁）、专注/休息时长、坐姿提醒开关。

### 6.7 权限与前台服务

- 复用现有 `RECORD_AUDIO` + `CAMERA` 权限与 `microphone|camera` 前台服务声明，无需改 Manifest。
- 进入陪学模式时显式弹窗说明：“摄像头只对准作业本/书本，按需拍摄，不上传视频，不保存照片”。
- 陪学会话期间前台通知显示“陪学模式进行中”，退出即恢复普通状态。

## 7. 隐私、安全与教育原则

1. **数据最小化**：按需拍照、帧即用即弃、不落盘、不录像；只上传为完成当前识别必需的单帧图片。
2. **本地优先**：会话报告、题目缓存、阅读记录全部存应用私有目录（DataStore），不开启云备份（现有 `allowBackup=false`）。
3. **家长控制**：直接答案、使用时长上限、坐姿提醒由家长设置；答案策略解锁需要家长验证。
4. **透明可退出**：模式内随时一句“结束陪学”或点按钮退出，退出后立即停止计时并清理相机资源。
5. **教育红线**：默认不直接给答案，讲解必须走提示阶梯；批改结论标注“AI 辅助，仅供参考”，错题订正建议由家长最终确认。
6. **隐私说明更新**：`PrivacyScreen` 增加“陪学模式”条目，说明相机与转写数据的用途、去向和保存方式。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 手写体/公式识别不准 | 误批改、讲错题 | 置信度低于阈值不做判断，明说“这题小智看不清，你念给我听”；报告标注不确定项 |
| LLM 不遵守“不给答案” | 家长不信任 | 工具结果注入硬规则 + 提示阶梯状态机 + 服务端人格强化；答案策略为家长可见开关 |
| 儿童语音 ASR 准确率低 | 陪读评测误差 | 逐句短文本评测、拼音级容错、麦克风距离引导；评测结果标注“仅供参考” |
| 相机长时间使用发热、隐私顾虑 | 体验与信任受损 | MVP 按需拍摄；P1 连续功能也限定间隔（≥5 分钟）且只在开启坐姿提醒时工作 |
| TTS 回声干扰评测 | 误判孩子读错 | 领读采用轮替半双工，小智读时不采集评测 |
| 单帧开相机耗时 1-2 秒 | 互动有延迟 | 可接受为 MVP；P1 做会话内相机复用与预览取景 |

**验收标准**

1. 语音说“陪我写作业/陪我读书”能进入对应模式，结束语音能退出并生成报告。
2. 同一页连问多题只拍一次；说“重新看”会重拍。
3. 默认策略下连续追问同一题，提示逐级升级且不直接给答案。
4. 检查作业后，正确/错误/看不清三种状态在 UI 与语音播报中一致。
5. 陪读模式下漏字、明显错字能被指出，同音字不误报为错误。
6. 陪学期间前台通知正确显示，退出后不再持有相机。
7. 报告可查看、导出、删除，删除后无残留。

## 11. 附：推荐服务端导师人格（可选）

> 你是小智，一位耐心、温和的学习陪伴者。规则：1）孩子问作业时，先复述题目关键信息，再给提示，不给最终答案；2）同一题孩子连续表示不会，才逐步升级提示层级；3）孩子答对时具体表扬努力过程；4）孩子答错时不批评，指出具体卡点并鼓励再试一次；5）每次讲解不超过孩子当前年级应会的表达；6）看不清题目时直接说明并请孩子念出题目；7）休息时间到时提醒孩子放松眼睛。
